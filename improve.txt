Посмотрел текущую реализацию. У тебя уже **не “начало MVP”**, а нормальный рабочий vertical slice: React/TS → FastAPI → local `faster-whisper small` → PII masking → `gpt-4.1-mini` → structured draft → review → МКБ-10 → approve → DOCX. Плюс JWT, audit edits, Docker Compose и 6 шаблонов. На тестовой записи ~359 секунд STT занял ~98 секунд, LLM — ~10 секунд. :chatgpt-content-reference{index="1"} :chatgpt-content-reference{index="2"}

Поэтому я бы **не тратил время на переписывание архитектуры**. Модульный монолит здесь правильный. Нужно превратить текущий MVP в демо, после которого понятно: «это уже почти продукт».

## P0 — обязательно для мощного демо

### 1. PDF — однозначно делаем

Сейчас у тебя DOCX уже работает, но PDF отсутствует, а сопоставление шаблонов привязано к структуре DOCX. :chatgpt-content-reference{index="3"}

После approve должно быть:

```text
Документ подтвержден ✓

[ 👁 Предпросмотр ]
[ 📄 Скачать PDF ]
[ 📝 Скачать DOCX ]
[ → Передать в МИС ]
```

Я бы генерировал:

```text
approved JSON
      ↓
DocumentRenderer
      ├── DOCXRenderer
      └── PDFRenderer
```

Не:

```text
DOCX → PDF
```

а оба из одного `ApprovedConsultation`.

Так PDF и DOCX являются разными представлениями одного immutable документа.

# 3. Source Grounding — самая сильная фича

Вот это я бы поставил даже **выше vector DB**.

У тебя сейчас Whisper уже хранит segments с timestamps, но extracted fields не связаны с источником. Это прямо отмечено как направление улучшения. :chatgpt-content-reference{index="4"}

Сделай:

```text
Жалобы

┌──────────────────────────────────────────┐
│ Сухой кашель                            │
│                                          │
│ 🎙 Источник 00:32                        │
│ "третий день сухой кашель..."           │
└──────────────────────────────────────────┘
```

Нажимаешь:

**`🎙 00:32`**

и аудио перескакивает именно туда.

То же самое:

```text
Парацетамол
500 мг

Источник:
01:13 → "парацетамол пятьсот миллиграмм"
```

### Для этого меняем LLM output

Не только:

```json
{
  "diagnosis": "Острый бронхит"
}
```

а:

```json
{
  "diagnosis": {
    "value": "Острый бронхит",
    "evidence": [
      {
        "segment_id": 31,
        "quote": "предварительный диагноз острый бронхит"
      }
    ]
  }
}
```

Тогда врач видит:

> **Почему AI заполнил это поле?**

Это очень хорошо закрывает проблему доверия к AI.

# 8. МКБ-10 сделать умнее

Сейчас у тебя уже отличный фундамент: **14 380 кодов + RU/KZ поиск**, а окончательный код выбирает врач. :chatgpt-content-reference{index="9"}

Я бы не давал LLM назначать МКБ.

Но сделал:

```text
Диагноз:
Острый бронхит

Возможные совпадения:

○ J20.9 Острый бронхит неуточненный
○ J20.8 Острый бронхит, вызванный другими агентами
○ ...

[Поиск вручную]
```

Называть это **«поиск по справочнику»**, а не AI-диагностикой.

И здесь как раз можно потом использовать embeddings/pgvector для semantic search.

# 9. pgvector — но только здесь

Я бы сейчас использовал vector DB **не для RAG по всей медицине**, а для двух конкретных вещей:

```text
Medical Knowledge
├── ICD-10 RU
├── ICD-10 KZ
├── medications
├── medical terminology
├── abbreviations
└── synonyms RU ↔ KZ
```

PostgreSQL уже предусмотрен проектом, поэтому:

```text
PostgreSQL + pgvector
```

никакого отдельного Qdrant.

Например:

```text
"воспаление бронхов"
       ↓ embedding
pgvector
       ↓
J20.9 Острый бронхит
```

Идеальная концепция:

```text

        ↓
```

Не надо пока автоматически понимать любой DOCX.

## Я бы расставил задачи именно так

**Сначала:** PDF + preview → source grounding/timestamps → красивый processing flow → PII visualization → editable transcript.

**Потом:** medical normalization → semantic ICD search/pgvector → dashboard + AI quality → template manager.

**После хакатона:** PostgreSQL production migration → job queue → полноценная diarization → real MIS → template versioning/hash → immutable approved artifacts → улучшение security.

Самая важная мысль: **не добавляй сейчас ещё десять AI-технологий.** У тебя уже работает AI pipeline. Теперь выигрыш даст **UX доверия**: врач видит, *что услышал AI → откуда взялось каждое поле → что было обезличено → что изменил врач → какой финальный PDF ушёл в МИС*. Именно это превратит текущую реализацию из «Whisper + GPT demo» в цельный MedTech-продукт.
