# Doctor workspace implementation

Implemented the React/TypeScript Vite doctor workspace in `src/`. The original entry page is preserved at `legacy/index.html`; `static/` originals remain untouched. The new page uses Tailwind, Radix dialog/slot primitives, React Hook Form, Zod and TanStack Query.

The Russian UI includes JWT login and session restore, consultation history/search and creation, template selection, recorder/file upload, synthetic demo transcript action, transcript views, clinical editing, ICD-10 lookup, audit history, save then approve controls, authenticated DOCX download and explicit mock MIS export. Every shared clinical field is editable, including medications, vitals and specialty fields from the selected DOCX catalog. The ICD code is chosen explicitly and does not change the free-text diagnosis. Empty specialty values remain null. No patient data is written to persistent browser storage; the JWT is session-only and the selected opaque consultation ID is retained in the URL for refresh.

MediaRecorder requests permission, negotiates WebM/MP4, stops before upload, releases tracks on completion/unmount/error, suppresses partial upload after errors, and caps uploads at 50 MiB. File selection checks size/format and normalizes common MIME variants. API calls have safe errors; live mode does not substitute fixture data. Fonts use local system faces and the frontend makes no font CDN request.

`npm test`: 6 tests passed, covering full clinical field round-trip, specialty keys, selected ICD code, save/approve version flow, normal refetch preservation of unsaved edits and deliberate regeneration reset. `npm run build`: passed (TypeScript and Vite production build). Vite reports a non-fatal bundle-size warning for the main chunk and harmless Rollup comments from Zod. Root's browser pipeline reached login, consultation, template, demo transcript, document review, ICD selection, approved DOCX and mock export. Its initial screenshots exposed fieldset overflow and stale approval copy; the CSS constraints and copy were updated afterward, pending the root's final mobile rerun.
