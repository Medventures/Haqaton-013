# Техническое задание — AI Medical Scribe

## 1. Назначение системы

Разработать веб-сервис для автоматического формирования листа врачебной консультации на основе разговора врача и пациента.

Система должна:

```text
Разговор врача и пациента
          ↓
Запись аудио
          ↓
Speech-to-Text
          ↓
Транскрипция
          ↓
Маскирование персональных данных
          ↓
LLM
          ↓
Структурированный лист консультации
          ↓
Проверка и редактирование врачом
          ↓
Подтверждение
          ↓
МИС
```

Основная цель — уменьшить время, которое врач тратит на ручное заполнение документации после/во время приёма.

**Принцип системы:**

> AI формирует черновик документа. Финальное решение и подтверждение всегда остаётся за врачом.

# 10. PII Guard

Перед отправкой текста в OpenAI выполняется обезличивание.

Обнаруживать минимум:

```text
ИИН
ФИО
телефон
email
адрес
дата рождения
номер документа
```

Например:

```text
Исходный текст:

Иванов Иван Иванович,
ИИН 010203500123,
телефон +7 701 123 45 67.
```

превращается в:

```text
[PATIENT_NAME],
ИИН [PATIENT_IIN],
телефон [PATIENT_PHONE].
```

### Важное правило

В OpenAI отправляется:

```text
masked_transcript
```

а не:

```text
raw_transcript
```

PII mapping не отправляется во внешний API.

# 13. Главное правило LLM

LLM является **information extraction engine**, а не врачом.

System instruction должна содержать правило примерно следующего содержания:

```text
You are an information extraction system
for medical consultation documentation.

Extract only information explicitly present
in the transcript.

Do not diagnose the patient.

Do not create medications, symptoms,
measurements or recommendations that
were not explicitly mentioned.

If information is absent, return null
or an empty collection.

Preserve medication names, dosages,
measurements and clinical terminology.

Return data according to the provided schema.
```

# 14. Consultation Schema

Первоначально предлагаю такую структуру:

```python
class Medication(BaseModel):
    name: str
    dosage: str | None
    frequency: str | None
    duration: str | None


class VitalSigns(BaseModel):
    temperature: str | None
    blood_pressure: str | None
    heart_rate: str | None
    respiratory_rate: str | None
    oxygen_saturation: str | None


class ConsultationData(BaseModel):

    complaints: list[str]

    anamnesis_morbi: str | None
    anamnesis_vitae: str | None

    allergies: list[str]

    medications: list[Medication]

    vital_signs: VitalSigns | None

    objective_status: str | None

    diagnosis: str | None

    recommendations: list[str]

    prescribed_medications: list[Medication]

    additional_notes: str | None
```

Но **перед финальной реализацией эту схему нужно привести один в один к реальному листу консультации UMC/МИС**.

Это одна из первых задач проекта.

# 16. Валидация

Нельзя доверять непосредственно JSON от LLM.

Pipeline:

```text
OpenAI
 ↓
Structured Output
 ↓
Pydantic
 ↓
Business validation
 ↓
ConsultationDraft
```

Проверять:

```text
JSON schema
required fields
field lengths
enum values
medication structure
unexpected fields
```

При ошибке допускается **одна автоматическая повторная попытка**.
