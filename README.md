# MedHub — AI Medical Scribe

**Команда:** Medventures — _участники: заполнить_

## Проблема

Врач тратит значительную часть приёма и время после него на ручное заполнение листа консультации. Это отнимает время у пациента, приводит к неполным записям и ошибкам при переносе в МИС.

## Решение

MedHub превращает аудиозапись консультации в структурированный черновик медицинского документа, который врач проверяет, исправляет и подтверждает.

**Принцип:** AI готовит черновик — медицинское решение и подтверждение всегда остаются за врачом.

```text
Запись / загрузка аудио
  → faster-whisper (локально) → транскрипция с сегментами
  → нормализация + маскирование ПДн (ИИН, ФИО, телефоны, адреса…)
  → OpenAI (gpt-4.1-mini) → структурированный черновик + ссылки на фрагменты записи
  → проверка и правка врачом, выбор кода МКБ-10
  → подтверждение → DOCX / PDF с QR-проверкой → MockMIS
```

Во внешний LLM уходит только замаскированный текст и описание полей формы; аудио остаётся на сервере.

### Возможности

- Запись с микрофона или загрузка WebM / WAV / MP3 / M4A (до 50 МиБ).
- Локальное распознавание речи (faster-whisper, CPU/int8), измеренные этапы и время обработки.
- Маскирование персональных данных перед отправкой в OpenAI, счётчики и подсветка найденных ПДн.
- Исправление транскрипции с версиями; после правки черновик помечается устаревшим и требует повторной генерации.
- Извлечение данных в одну из шести форм (терапевт, первичный осмотр терапевта, кардиолог, педиатр, проктолог, хирург).
- «Источник AI-версии»: каждое поле связано с фрагментом записи, с переходом к моменту в аудио.
- Поиск по справочнику МКБ-10 (14 380 кодов, RU/KZ).
- Справочные ссылки на клинические протоколы РК по каталогу `diseases.json` (без передачи данных пациента).
- Подтверждение документа, защита от устаревших версий (`409`), журнал правок.
- Выгрузка DOCX по исходному бланку и PDF с предпросмотром; PDF выпускается один раз на версию, хранится с SHA-256 и публичной страницей проверки по QR.
- Экспорт в MockMIS (заглушка).
- JWT-авторизация, Argon2, роли врач/администратор, очистка аудио по сроку хранения.

## Запуск

### Docker Compose (Nginx + API + PostgreSQL)

```bash
cp .env.example .env        # при необходимости задать JWT_SECRET, OPENAI_API_KEY и др.
docker compose up --build
```

Приложение: `http://localhost:8080`. Миграции Alembic применяются автоматически при старте API.

Дополнительные конфигурации:

- `compose.tls.yaml` — HTTPS через Nginx (`TLS_CERT_DIR` с `fullchain.pem` и `privkey.pem`);
- `compose.secrets.yaml` — загрузка секретов из файлов.

### Локальная разработка

Требования: Python 3.12+, Node.js 22, ffmpeg-совместимые библиотеки для PyAV.

```bash
# backend
python -m venv .venv
.venv/bin/pip install -e "backend[dev]"
cp .env.example .env
cd backend
# в demo миграции применяются при старте; в live — вручную с теми же переменными:
# set -a; . ../.env; set +a; ../.venv/bin/alembic upgrade head
../.venv/bin/python -m uvicorn app.main:app --env-file ../.env --host 127.0.0.1 --port 8000

# frontend (в другом терминале, из корня)
npm install
npm run dev                 # http://localhost:5173, /api проксируется на :8000
```

По умолчанию локально используется SQLite (`storage/medhub.db`). При первом распознавании загружается модель Whisper.

Синтетическая демо-база: `python scripts/seed_demo.py`.

### Переменные окружения

Полный список с комментариями — в [.env.example](.env.example). Основные:

| Переменная | Назначение |
|---|---|
| `APP_MODE` | `demo` (демо-вход) или `live` (требует `DOCTOR_PASSWORD_HASH`, демо-пароль запрещён) |
| `LLM_PROVIDER` | `auto` (demo → встроенный пример, live → OpenAI) или `openai` |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | Доступ к OpenAI, по умолчанию `gpt-4.1-mini` |
| `JWT_SECRET` | Секрет подписи токенов |
| `DOCTOR_USERNAME`, `DOCTOR_PASSWORD_HASH` | Учётная запись врача (Argon2-хеш) |
| `WHISPER_MODEL`, `WHISPER_DEVICE`, `WHISPER_COMPUTE_TYPE` | Настройки распознавания (`small`, `cpu`, `int8`) |
| `DATABASE_URL` | SQLite локально, PostgreSQL в Compose |
| `PUBLIC_BASE_URL` | Внешний адрес для QR-ссылок в PDF (для реального использования — HTTPS) |
| `AUDIO_RETENTION_DAYS`, `MAX_UPLOAD_MB` | Срок хранения аудио и лимит загрузки |

## Что готово

Работает полный путь **аудио → транскрипция → маскирование → AI-черновик с источниками → проверка врачом → МКБ-10 → подтверждение → DOCX/PDF → MockMIS**. На тестовой записи ~6 минут распознавание заняло ~98 с на CPU, генерация черновика — ~10 с.

### Известные ограничения

- Интеграция с реальной МИС не реализована — только MockMIS.
- Нет диаризации (врач/пациент) и потокового распознавания во время разговора.
- Маскирование ПДн эвристическое (регулярные выражения) и не гарантирует анонимность; исходный текст хранится в локальной БД.
- Длительные операции выполняются внутри процесса API, без очереди задач; несколько экземпляров API без доработки не поддерживаются.
- Нет ограничения попыток входа, MFA, управления пользователями и отзыва сессий.
- Качество распознавания и извлечения не проверено на репрезентативном корпусе RU/KZ; ссылка на источник подтверждает происхождение фрагмента, а не клиническую правильность.
- Сопоставление полей DOCX привязано к структуре конкретных бланков; редактора шаблонов нет.
- Справочник протоколов — вспомогательный и не оценивает соответствие лечения протоколу.

Перед использованием с реальными пациентами необходимы HTTPS, стойкие учётные данные, резервное копирование и согласование внешней обработки данных — см. раздел 14 в [docs/system-description.md](docs/system-description.md).
